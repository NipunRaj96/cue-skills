# Cue v0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build `cue-skills` v0. It forces coding agents to load the user's chosen skills through hooks and plugins, across agents and surfaces.

**Architecture:** One Node core (catalog, rules, selection, rendering, session state, log) runs behind a single `engine.run()`. Thin per-surface adapters translate each agent's hook input and output. Hook-based agents call `cue-skills hook <surface> <event>`. Plugin-based agents (OpenCode, OpenClaw) import the engine in-process.

**Tech Stack:** Node 18 or later, ESM, plain JS. The only runtime dependency is `yaml`. Tests use `node:test` and `node:assert/strict`.

**Spec:** `docs/superpowers/specs/2026-10-18-cue-v0-design.md`

## Global Constraints

- Node 18 or later, `"type": "module"`. The only runtime dependency is `yaml`, with no dev dependencies.
- Hooks fail open: on any error they exit 0 with empty stdout, and the error is logged to `~/.cue/log.jsonl`.
- Hook latency must stay under 100 ms. No network calls in any code path.
- The render budget is 9,000 characters per injection. A skill whose body overflows becomes the line `Read <path> and follow it.`
- Injected wording is factual. The reminder line format is exactly `Active skills: name (desc), name (desc).` Each description is truncated to 80 characters.
- Every config edit writes `<file>.bak` first, is idempotent, and finds Cue's entries by the substring `cue-skills hook`.
- All home paths resolve lazily through `os.homedir()`, so tests can set `process.env.HOME` to a temp directory.
- Git author is Nipun Kumar <nipunraj2004@gmail.com>. Never add `Co-Authored-By` lines or AI attribution in commits, files or package metadata.
- Commit messages follow Conventional Commits (`feat:`, `test:`, `docs:`).

## Review Focus

1. **Several installed versions of one plugin.** For example, superpowers 5.1.0, 6.4.1 and 7.0.0 under `~/.claude/plugins/cache`. Only the highest semver directory is scanned. Task 2 owns the test.
2. **Malformed `rules.yaml`.** The hook still exits 0 with empty output and logs the error. `status` prints the parse error. Tasks 3 and 5 own the tests.
3. **User config that already has other hooks** (caveman's, ponytail's). Install and uninstall leave them intact, and a second install adds no duplicates. Task 5 owns the test.
4. **Hook stdin that is empty or not JSON.** The hook outputs nothing and exits 0. Task 5 owns the test.
5. **Prompt words must match whole words.** The rule word `ui` must not match "build". Task 3 owns the test.

## Edge-case refinements (binding; each task owns its line)

- **T1:** `globToRegExp` callers normalise `\` to `/`. `writeJson` writes atomically: write `path.tmp-<pid>`, then `renameSync`.
- **T2:** The scan follows symlinks and guards against cycles with a `Set` of `realpathSync` values. Entries are sorted by path for determinism. An unreadable or unparseable `SKILL.md` is skipped, not thrown.
- **T3:** A string value for `always`, `never`, `use`, `prompt`, `files`, `project` or `skillDirs` is coerced to `[value]`. Any other non-array value pushes an error and is ignored. Word matching is Unicode-aware: `(?<![\p{L}\p{N}_])<escaped>(?![\p{L}\p{N}_])` with flags `iu`.
- **T4:** The full render header is `## Skill: <name>\nSkill dir: <dirname(path)>\n`, so relative references in a skill still resolve. `process.env.CUE_DISABLE === "1"` makes `run` return `{text:"", skills:[]}`. State files are written atomically (tmp file plus rename).
- **T5:** Claude also gets a `SubagentStart` hook. It maps to phase `system` (full bodies, stateless), so subagents inherit the skills. Output uses `hookEventName: "SubagentStart"`.

**Interfaces:**

    - A bare name prefers `kind` in the order project, then user, then plugin. The first match wins.

### Task 4: Render, state, log and engine

**Files:**
- Create: `src/render.js`, `src/state.js`, `src/log.js`, `src/engine.js`
- Test: `test/engine.test.js`

**Interfaces:**
- Consumes: `loadCatalog`, `loadRules`, `select`, `parseSkill`.
- Produces:
  - `render.js`:
    - `renderFull(entries: Entry[], budget = 9000): string`
      - Each skill is `## Skill: <name>\n<body without frontmatter>\n`, in order.
      - When adding a body would exceed the budget, emit `## Skill: <name>\nRead <path> and follow it.\n` instead.
    - `reminder(entries): string` returns exactly `Active skills: a (desc), b (desc).`, or `""` when there are no entries.
  - `state.js`: `loadState(agent, session): Set<string>`, `saveState(agent, session, set)`, `resetState(agent, session)`.
    - Files are `~/.cue/state/<agent>-<session>.json`.
    - The session id is sanitised to `[A-Za-z0-9_-]`.
    - Saving prunes state files with an mtime older than 7 days.
  - `log.js`: `logEvent(obj)` appends a JSON line with `ts` set to an ISO string. `readLog(n = 20): object[]`.
  - `engine.js`: `run({ agent, session = "default", phase, reset = false, prompt = "", files = [], cwd }): { text: string, skills: {name, reason}[] }`. Phases:
    - `"start"`: if `reset`, clear the state. Inject full bodies of every active skill not yet in the state, add them to the state, and append the reminder.
    - `"prompt"`: full bodies for active skills not in the state, plus the reminder.
    - `"tool"`: full bodies for newly active skills only, no reminder. Returns `""` if there are none.
    - `"system"`: full bodies of all active skills every time, no state, no reminder. Used by OpenCode and OpenClaw.
    - Each call logs `{ agent, session, event: phase, skills, chars, unresolved, errors }`.
    - Load order: `rules = loadRules(cwd)`, then `catalog = loadCatalog({ cwd, extraDirs: rules.skillDirs.map(expandHome) })`.
    - Wraps everything in try/catch. On error it logs `{ error: message }` and returns `{ text: "", skills: [] }`.
