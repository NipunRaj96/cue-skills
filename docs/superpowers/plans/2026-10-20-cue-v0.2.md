# Cue v0.2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Pick situational skills automatically from what is happening, correct drift from standing skills, show one visible line when Cue acts, and prove the picker offline. No setup beyond `npm i -g cue-skills && cue-skills init`.

**Architecture:** The catalog gains skill cards, duplicate collapse and a cached BM25 index. A pure pipeline (signals, then a query, then BM25 scores, then a decision, then an injection plan) runs inside `engine.run()` when an adapter passes `auto`. A pure caveman checker scores replies in an `observe` phase, and the result is fed back on the next prompt. The same pure pipeline runs offline in `bench/picker/eval.js` against frozen cards.

**Tech Stack:** Node 18 or later, ESM, plain JS. The only runtime dependency is `yaml`. Tests use `node:test` and `node:assert/strict`.

**Spec:** `docs/superpowers/specs/2026-10-20-cue-v0.2-design.md`. Its section "Scope and settled decisions" overrides everything earlier in it.

## Global Constraints

- Node 18 or later, ESM. The only runtime dependency is `yaml` (no new dependencies, dev or runtime). No network in any code path. There is no embedding re-ranker in v0.2: the seam is the `scored` array between `score()` and `decide()`.
- Tests run with `node --test test/*.test.js` (`npm test`). Every test sets `process.env.HOME` to a fresh temp dir (`fixture()` in `test/helpers.js`).
- Fail open. A hook exits 0 with empty stdout on any error, and `engine.run` never throws.
- Keep every v0.1 security guarantee:
  - project files are read only through `readChecked`/`readRegular` (`src/safefile.js`) with `{ base, nofollow: true }`;
  - project skills and rules count only when the project is trusted;
  - symlinks out of a project are never followed;
  - `~/.cue` files are mode 0600 and written atomically.
- Warm-cache hook latency stays under about 150 ms. BM25 runs over the cached cards and index in `~/.cue/catalog.json`.
- Agents:
  - Claude Code gets everything;
  - OpenCode and Antigravity get the picker and enforcer as best effort, with unit tests only;
  - Codex, Cursor, Gemini and OpenClaw keep exactly the v0.1 behaviour, because they never pass `auto`.
- Fixed numbers:
  - token estimate = `Math.ceil(chars / 4)`;
  - the per-turn cap is `CAP_TOKENS = 2000`;
  - a pick whose body is over `BODY_MAX_TOKENS = 1500` is injected as a card plus `Read <path>`;
  - a shortlist holds at most 3 entries;
  - standing skills without a checker are re-injected every `REINJECT_EVERY = 10` turns.
- Fixed copy:
  - shortlist header: `Relevant skills; read the file of the one that fits.`;
  - visible line: `cue → ` followed by the parts joined with `; `. Parts look like `frontend-design (design task)`, `shortlist: a, b, c (prompt)`, `caveman re-applied (drift)` and `ponytail re-applied (every 10 turns)`;
  - ask-mode line: `Begin your reply with this line: cue → …`;
  - drift note: `Previous reply did not follow caveman: N filler words.`

- Live testing (Task 12) happens only in Claude Code desktop sessions. Make no ollama, agy or OpenCode live calls.

## Rulings on spec gaps (binding)

1. **`when_to_use`.** None of the 99 installed skills has `when_to_use`, but 27 have `triggers`/`trigger`. So `when_to_use = meta.when_to_use ?? meta["when-to-use"] ?? [meta.triggers ?? meta.trigger].flat().join(", ")`, or `""`.
2. **Enforcer versus the 1,500-token rule.** The card rule applies to picker picks. A drift or periodic re-injection sends the full body: caveman is about 1,700 tokens and ponytail about 1,650. Enforcer bodies are admitted first, in standing order. A second body that would push the turn past `CAP_TOKENS` becomes a card. Picks get what is left.
3. **Collapse precedence and `resolve()`.** Precedence applies to picker cards only. `resolve()` for rules keeps the v0.1 order (project, user, plugin), so v0.1 behaviour is unchanged. A duplicate at the same kind is decided by the lexically smaller `path`.
4. **Where the visible line is shown.** In Claude, notices pile up in session state during a turn and the `Stop` hook prints them as one `systemMessage`. That gives one merged line per turn at zero model tokens. Agents without a visible channel (OpenCode, Antigravity) get the ask-mode line in the injected text instead.
5. **Test-failure signal.** Claude installs `PostToolUse` and `PostToolUseFailure`, both with matcher `Bash`. They share one handler. Task 12 checks which one fires.
6. **Project summary weight.** The project summary is appended to the first query of a session at query weight 0.5, so dependencies alone rarely fire a pick. The eval's neutral-with-project cases measure this.
7. **Antigravity.**
   - `PreToolUse` cannot inject context there, so Antigravity gets no tool signals.
   - The prompt comes from the `transcriptPath` tail: the `<USER_REQUEST>` of the last `USER_INPUT` line.
   - A turn is keyed by that line's `step_index`.
   - The reply comes from the last `PLANNER_RESPONSE` line, read in a new `Stop` hook.
8. **Subagents.** A subagent gets the standing full bodies (v0.1 `system`) plus the session's current picks as card blocks. It is stateless.
9. **Caveman thresholds.** These come from `bench/results/full-2026-10-19/runs.jsonl`. That directory is gitignored, so the numbers live in a code comment (Task 8). Length alone does not separate the modes, so it only counts together with filler.
10. **Eval cases.** Per the spec, the controller writes `bench/picker/cases.json`, not the Task 5 implementer. This also keeps labelling separate from threshold tuning.

### Task 2: BM25 index and scoring

**Files:**
- Create: `src/bm25.js`
- Modify: `src/catalog.js` (cache layout)
- Test: `test/bm25.test.js` (new)

**Interfaces:**
- Consumes: `collapse` and `Entry` from Task 1.
- Produces (`src/bm25.js`, pure and stdlib-free):
  - `STOPWORDS: Set<string>`, exactly: `a an the and or but if of in on at to for from by with as is are was were be been it its this that these those i me my we our you your he she they them do does did can could should would will just please any all some use using used when skill skills user`.
  - `tokenize(text: string): string[]`:
    1. lowercase;
    2. split on `/[^a-z0-9]+/`;
    3. drop tokens shorter than 2 characters and stopwords;
    4. stem by stripping one trailing `ing` or `ed` when at least 3 characters remain, then halving a final doubled consonant other than `ll`, `ss` or `zz` (`debugg` becomes `debug`); or else stripping a trailing `s` when the word does not end in `ss` and at least 3 characters remain.
  - `queryTerms(parts: {text: string, weight?: number}[]): Map<string, number>` maps each term to its maximum weight (default 1).
  - `buildIndex(cards: Entry[]): Index`, where `Index = { N, avgdl, df: Record<string, number>, docs: {len: number, tf: Record<string, number>}[] }`, aligned with `cards`.
    - Doc terms are 3 × `tokenize(name)` (with `-`, `_` and `:` read as spaces), plus `tokenize(description)` and `tokenize(when_to_use)`.
  - `score(index: Index, terms: Map<string, number>): {i: number, score: number}[]`:
    - BM25 with `k1 = 1.2`, `b = 0.75` and `idf = ln(1 + (N - df + 0.5) / (df + 0.5))`;
    - each term's contribution is multiplied by its weight;
    - only `score > 0` is returned, sorted by score descending, then `i` ascending.
- Produces (`src/catalog.js`):
  - `loadAll({ cwd, rules }): { entries, cards, index }`, where `cards = collapse(entries)` and `index = buildIndex(cards)`.
  - The cache file `~/.cue/catalog.json` becomes `{ v: 2, key, entries, cards, index }`. A cache whose `v !== 2` is rebuilt.
  - `loadCatalog(args)` returns `loadAll(args).entries`.

### Task 3: Signals to query

**Files:**
- Create: `src/signals.js`
- Test: `test/signals.test.js` (new)

**Interfaces:**
- Consumes: `readChecked` (`src/safefile.js`).
- Produces:
  - `EXPAND: {tool?: RegExp, file?: RegExp, words: string, label: string}[]`. The first match wins for the label, and every matching entry adds its words. Exact entries:

    | match | words | label |
    |---|---|---|
    | file `/\.(tsx\|jsx\|css\|scss\|sass\|less\|html\|vue\|svelte)$/i` | `frontend ui design component` | `frontend file` |
    | tool `/^mcp__stitch__\|figma/i` | `design ui replicate` | `design task` |
    | file `/(^\|\/)(tests?\|__tests__\|spec)\/\|\.(test\|spec)\.[a-z]+$\|_test\.(go\|py)$\|(^\|\/)test_[^/]+\.py$/` | `testing debug` | `test file` |
    | tool `/^mcp__.*(playwright\|chrome\|browser)/i` | `browser testing` | `browser tool` |
    | file `/(^\|\/)SKILL\.md$/` | `skill create write` | `skill file` |
    | file `/\.(apk\|xapk\|aar\|jar\|dex)$/i` | `android decompile reverse engineer` | `android package` |
    | file `/(^\|\/)\.github\/workflows\/\|(^\|\/)Dockerfile$/` | `ci deploy` | `ci config` |
    | file `/\.sql$\|(^\|\/)migrations?\//i` | `database migration` | `migration` |
    | file `/\.(png\|jpe?g\|webp\|svg)$/i` | `image` | `image file` |

  - `queryParts({ prompt = "", tool = "", file = "", failure = false, project = "" }): { parts: {text, weight}[], label: string }`:
    - `prompt` is added at weight 1;
    - the words of every matching `EXPAND` entry are added at weight 1;
    - for `mcp__*` tools, the tool name with `mcp__` and `_` read as spaces is added at weight 1;
    - `failure` adds `testing debug failure` at weight 1;
    - `project` is added at weight 0.5.
    - `label` is `test failure` when `failure`; else the first matching `EXPAND` label; else `prompt` when there is a prompt; else `tool`.
  - `testFailure({ command = "", output = "", exitCode = null }): boolean` is `RUNNER.test(command) && exitCode !== 0 && FAILED.test(output)`. A `null` exit code counts as unknown, which is not 0. The regexes:
    - `RUNNER = /\b(npm (run )?test|pnpm test|yarn test|npx (jest|vitest|mocha)|jest|vitest|mocha|pytest|go test|cargo test|node --test|rspec|phpunit|dotnet test|mvn test|gradle test)\b/`
    - `FAILED = /\b\d+ (failed|failing)\b|^FAIL\b|^not ok \d+|AssertionError|✗|✖|\bFAILED\b|Tests? failed/m`
  - `DEP_WORDS: Record<string, string>`:
    - `react`, `react-dom`, `next`, `vue`, `nuxt`, `svelte`, `@sveltejs/kit`, `@angular/core`, `solid-js`, `astro` map to `frontend ui`;
    - `tailwindcss`, `styled-components`, `@emotion/react`, `sass` map to `css design`;
    - `framer-motion`, `motion`, `gsap` map to `animation motion`;
    - `three`, `@react-three/fiber` map to `3d webgl`;
    - `express`, `fastify`, `koa`, `hono` map to `server api`;
    - `jest`, `vitest`, `mocha`, `@playwright/test`, `cypress` map to `testing`;
    - `prisma`, `drizzle-orm`, `typeorm`, `sequelize`, `mongoose` map to `database`.
  - `MARKERS: Record<string, string>`:
    - `tsconfig.json` maps to `typescript`;
    - `pyproject.toml` and `requirements.txt` map to `python`;
    - `go.mod` maps to `go`;
    - `Cargo.toml` maps to `rust`;
    - `Gemfile` maps to `ruby`;
    - `pom.xml` and `build.gradle` map to `java`;
    - `AndroidManifest.xml` maps to `android`.
  - `summarize({ deps = [], markers = [] }): string` returns the unique words in first-seen order, joined with spaces. Raw dependency names are never included.
  - `projectSummary(root: string): string`:
    - reads `root/package.json` with `readChecked(p, 256 * 1024, { base: root, nofollow: true })` (dependencies plus devDependencies);
    - detects markers with `lstatSync(join(root, m)).isFile()`, so symlinks are ignored;
    - returns `""` on any problem.

### Task 4: Decision, token cap and rendering

**Files:**
- Create: `src/pick.js`
- Test: `test/pick.test.js` (new)

**Interfaces:**
- Consumes: `score`, `queryTerms` (Task 2); `renderFull` (`src/render.js`); `readChecked`; `MAX_SKILL`.
- Produces:
  - Constants:
    - `THRESHOLDS = { hi: 6, lo: 3, margin: 1.5 }`, a placeholder that Task 5 overwrites with the tuned values;
    - `CAP_TOKENS = 2000`, `BODY_MAX_TOKENS = 1500`, `SHORTLIST_MAX = 3`;
    - `SHORTLIST_HEADER = "Relevant skills; read the file of the one that fits."`.
  - `decide(scored: {card: Entry, score: number}[], t = THRESHOLDS): { kind: "confident"|"shortlist"|"none", picks: Entry[] }`:
    - `confident` when `top >= t.hi && top >= t.margin * second` (where `second` is 0 if absent); `picks` is `[top]`;
    - else `shortlist` holding the cards with `score >= t.lo`, up to 3;
    - else `none`.
  - `pickStep({ cards, index, parts, exclude = new Set(), thresholds = THRESHOLDS }): Decision` scores `queryTerms(parts)`, then drops cards that are `invocable_only` or whose `name` is in `exclude`, then calls `decide`.
  - `cardBlock(card): string` returns `## Skill: <name>\n<purpose>\nRead <path> and follow it.\n`. Here `purpose` is the description with whitespace collapsed, cut to 160 characters.
  - `listLine(card): string` returns `- <name>: <description collapsed, cut to 100 chars> (<path>)`.
  - `planInjection(decision, { cap = CAP_TOKENS } = {}): { items: {card, mode: "full"|"card"|"list"}[], tokens: number }`. It is pure and reads no files.
    - The token cost of `full` is `card.tokens + 15`. The cost of `card` and `list` is `Math.ceil(text.length / 4)`; the shortlist header costs once.
    - **Confident:** `full` if `tokens <= BODY_MAX_TOKENS` and it fits; else `card` if it fits; else nothing.
    - **Shortlist:** the header plus `list` lines while they fit.
  - `renderPlan(plan): string`:
    - `full` goes through `renderFull([card], Infinity)`;
    - `card` and `list` go through the functions above, with the shortlist header line first;
    - a `kind: "project"` card in `card` or `list` mode is dropped unless `readChecked(path, MAX_SKILL, { base: card.base || "\0", nofollow: true }).data` succeeds.

      - `top1` is the share of positives where the first injection's `picks[0]` is in `expect`;
      - `hit` is the share of positives where any pick from any step is in `expect`;
      - `falseFire` is the share of neutral cases with any injection;
      - `forbidHits` is the number of cases that injected a `forbid` skill;
      - `tokensPerCase` is the mean of the summed `plan.tokens` over all cases;

      - objective: maximise `top1 + hit` subject to `falseFire <= 0.10` and `forbidHits == 0`;
      - ties go to the lower `tokensPerCase`, then the higher `hi`.

      - it prints a Markdown table of the tune and test metrics under the shipped `THRESHOLDS`, plus the outcome of case `stitch-to-frontend`;
      - with `--tune`, it prints the tuned thresholds first and evaluates with those.

  - The thresholds, with a comment that records the data:

    ```js
    // From bench/results/full-2026-10-19/runs.jsonl (459 rows, 5 agents; gitignored):
    // prose filler ratio, mode none: median 0.096, p10 0.038; mode manual (caveman pasted): median 0.000, p90 0.020.
    // FILLER_MAX 0.04 with MIN_WORDS 20 flags 85% of none replies and 2% of manual replies.
    // Length alone does not separate modes (>3x session median: none 23%, manual 24%), so it counts only with filler > 0.02.
    export const FILLER_MAX = 0.04, MIN_WORDS = 20, LENGTH_X = 3, LENGTH_FILLER = 0.02, MIN_HISTORY = 2;
    ```

  - `checkCaveman(reply: string, history: number[]): { ok: boolean, note: string }`:
    - prose words are `stripCode(reply).toLowerCase().match(/[a-z']+/g)`, with `n` the count and `f` the number of `FILLER` words;
    - if `n >= 20 && f / n > 0.04`, the note is `Previous reply did not follow caveman: ${f} filler words.`;
    - else, if `history.length >= 2`, `words > 3 × median(history)` and `f / n > 0.02`, the note is `Previous reply did not follow caveman: ${words} words, ${x.toFixed(1)}x the session median.`. Here `words` counts `\S+` and the median is the lower middle;
    - else `{ ok: true, note: "" }`.
  - `CHECKERS: Record<string, (reply, history) => {ok, note}> = { caveman: checkCaveman }`.
- Engine changes:
  - **observe:** skip all checks when `reply.trim()` is empty. Otherwise, for each standing entry with `CHECKERS[name]`, push `{ name, note }` to `s.drift` on failure. Then `s.replies = [...s.replies, words].slice(-20)`.
  - **Auto block, on `newTurn`, before the picker** (Ruling 2):
    - for each drift item: the note line, then that skill's full body through `renderFull([entry], Infinity)`, or `cardBlock(entry)` once `s.turnTokens` would pass `CAP_TOKENS`; push the notice `${name} re-applied (drift)`; then clear `s.drift`;
    - for each standing entry without a checker, when `s.turn % REINJECT_EVERY === 0`: the same rendering, with the notice `${name} re-applied (every 10 turns)`.
